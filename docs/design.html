Wizard Web Admin

ระบบหลังบ้านที่สร้างตาม Workflow ของ Wizard โดยตรง พนักงานทุกฝ่ายเพิ่ม แก้ไข อัปเดต และตรวจข้อมูลได้จากที่เดียว ข้อมูลทั้งหมดเก็บในฐานข้อมูลกลาง ในอนาคต LINE OA, AI Voice และระบบอื่นจะอ่านจากชุดเดียวกันนี้ ไม่ต้องกรอกซ้ำ

รอการยืนยัน Blueprint ก่อนเริ่มเขียนระบบ

ความจริงชุดเดียวแก้ราคาที่เดียว ทุกช่องทางเห็นตรงกันทันที ไม่ต้องไปแก้ใน LINE หรือ Voice อีก
ข้อมูลธุรกิจแยกจากเอกสารราคา สาขา โปรโมชั่น บริการ และกฎ เก็บเป็นตาราง ส่วนเอกสารเป็นแค่ข้อมูลอ้างอิง ถ้าสองแหล่งขัดกัน ให้ยึดตาราง
รู้ทุกการเปลี่ยนแปลงรู้ว่าใครแก้อะไร เมื่อไหร่ ย้อนดูเวอร์ชันเก่า และกู้คืนได้ทุกรายการ
รองรับข้อมูลจำนวนมากค้นหาและกรองได้เร็ว นำเข้าไฟล์ใหญ่ทีละชุดได้ โดยตรวจก่อนบันทึกทุกครั้ง

ภาพรวมระบบ

ตอนนี้ทุกอย่างทำงานบนเครื่องคอมพิวเตอร์ (Local) ทีมงานใช้ผ่านเว็บเบราว์เซอร์ ช่องทางอื่นจะมาต่อทีหลังโดยอ่านข้อมูลจากฐานข้อมูลเดียวกัน

ผู้ใช้งาน

มี 4 บทบาท แต่ละคนเห็นเฉพาะเมนูที่เกี่ยวกับงานของตัวเอง

Admin

ดูแลระบบ
  • สร้างและปิดบัญชีพนักงาน กำหนดสิทธิ์
  • นำเข้าข้อมูลชุดใหญ่
  • ตรวจประวัติทั้งระบบ และกู้คืนข้อมูล

Manager

ผู้อนุมัติ
  • ตรวจและอนุมัติการแก้ไขก่อนเผยแพร่
  • แก้ราคา สาขา และ Business Rules
  • มอบหมาย Ticket และดูภาพรวมใน Dashboard

Marketing

ผู้ดูแลเนื้อหา

  • ทุกการแก้ไขต้องรอ Manager อนุมัติ

Call Center

ผู้ใช้ข้อมูลตอบลูกค้า

  • บันทึกการโทร เปิด Ticket และใช้ Outbound Script
  • เสนอ FAQ ใหม่จากคำถามจริงของลูกค้า

13 เมนู		 สร้างเองตามธุรกิจออกแบบทุกหน้าให้ตรงกับงานจริง สำเร็จรูปแต่ต้องดัดแปลงได้หน้าจอรายการกับฟอร์มทันที แต่ Import, Tickets และ Call ต้องเขียนเสริมภายในกรอบของ CMS สร้างเองตามธุรกิจออกแบบทุกหน้าให้ตรงกับงานจริง
Login + สิทธิ์ ใช้ชุดสำเร็จรูปใช้ไลบรารี Login ที่นิยม แล้วกำหนดสิทธิ์เอง มีในตัว มีในตัว
ประวัติ + Audit สร้างครั้งเดียวที่ฐานข้อมูลจับทุกการเปลี่ยนแปลง ไม่ว่าจะมาจากหน้าจอ การ Import หรือระบบอื่น มีในตัวจับได้เฉพาะการแก้ที่ผ่าน CMS สร้างเอง
ช่องทางให้ระบบอื่นอ่าน สร้างเองตอนต้องใช้ออกแบบให้เหมาะกับ LINE และ Voice มีในตัว มีในตัว
ฐานข้อมูล ตารางตามภาษาธุรกิจPostgreSQL ของเราเอง ย้ายไปไหนก็ได้ โครงสร้างตามแบบ CMSระบบอื่นต้องอ่านผ่าน CMS PostgreSQL ใน Supabaseถ้าจะขึ้น AWS ต้องติดตั้ง Supabase เองซึ่งมีหลายส่วน
สีทอง สร้างเองให้ตรงธุรกิจ สีเขียว ใช้ของสำเร็จรูปได้เลย สีส้ม สำเร็จรูป แต่ไม่ตรงกับงาน ต้องดัดแปลง

  1. งานส่วนใหญ่เป็น Workflow ไม่ใช่แค่ฟอร์มกรอกข้อมูล จาก 13 เมนู มีเพียงส่วนน้อยที่ CMS ช่วยได้เต็มที่ Import ที่ต้องตรวจซ้ำและขัดแย้ง, Tickets, Call History, Dashboard และการอนุมัติ ต้องสร้างเองไม่ว่าเลือกทางไหน
  2. ฐานข้อมูลตั้งชื่อตามภาษาธุรกิจ เช่น ตารางบริการ ราคา สาขา LINE OA, AI Voice และ Odoo จึงเข้าใจและอ่านได้ตรง ไม่ต้องแปลงจากโครงสร้างของ CMS
  3. ประวัติบันทึกที่ฐานข้อมูล ไม่ว่าข้อมูลจะเปลี่ยนจากหน้าจอ จากการ Import หรือจากระบบอื่นในอนาคต ก็ถูกบันทึกทุกครั้ง
  4. ไม่ผูกกับผู้ให้บริการใด วันนี้รันบนเครื่อง วันหน้าย้ายขึ้น AWS ได้โดยไม่ต้องรื้อระบบ

สิ่งที่ต้องแลก: ช่วงแรกช้ากว่า Payload เพราะต้องทำ Login, สิทธิ์ และประวัติเอง แต่ทั้งหมดทำครั้งเดียวในเฟส 1 แล้วทุกเมนูใช้ร่วมกัน ตัวเลือก C ก็ใช้ได้ดี แต่ถ้าแผนระยะยาวคือ AWS จะยุ่งกว่า A โดยไม่ได้ประโยชน์เพิ่ม

รายละเอียดทางเทคนิคของตัวเลือก A (สำหรับทีมพัฒนา)
  • Next.js + TypeScript ทำทั้งหน้าจอและ API ในโปรเจกต์เดียว
  • PostgreSQL รันบนเครื่องผ่าน Docker ภายหลังย้ายไป AWS RDS ได้
  • ประวัติและ Audit ใช้ trigger ของฐานข้อมูลเก็บข้อมูลก่อนและหลังการแก้ พร้อมผู้แก้ เวลา และที่มา
  • Login ใช้ไลบรารีมาตรฐาน (จะเลือกตอนเริ่มเฟส 1)
  • ไฟล์เก็บในโฟลเดอร์บนเครื่องก่อน ภายหลังย้ายไป S3

ตัวเลือกอื่นที่ดูแล้วแต่ไม่แนะนำ: Directus (license ฟรีเฉพาะองค์กรที่รายได้ต่ำกว่า $5M และพนักงานไม่ถึง 50 คน), Retool และ Appsmith (หน้าจอยืดหยุ่นน้อย และตัวระบบไม่ได้เป็นของเราเอง)
